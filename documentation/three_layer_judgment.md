# 三层判定（事件 / 素材 / 表述）——方法与实现

> 这是本项目的核心方法论，不是"再加一层流程"。混层是这个领域最常见的误判来源，
> 也是"辟谣被反驳、核查被抓住"的主要成因。本文分两部分：
> **判什么**（方法）、**怎么落成代码**（`prototype/evidence_rules.py`）。

## 1. 为什么要分三层

"这条是假新闻"这句话，实际上混了三个完全不同的问题：

| 层 | 问题 | 判错的后果 |
|---|---|---|
| **事件层** | 这件事本身发生了吗？ | 把真事件说成假 = 造新谣 |
| **素材层** | 配图/视频/音频是不是这个事件的？ | 事件真但画面假，整体当"真"放过去 |
| **表述层** | 说法是否超出证据？ | 事件真、画面真，但"彻底摧毁""全部投降"是夸大 |

三条实测例子（都来自本仓库 `dataset/`，可逐句复核）：

1. **事件假 + 素材假**（`factcheck__snopes_002`，Ilhan Omar 出逃摩洛哥）
   Snopes 评级 `False`；原文另点出"同一账号还发了一张 **AI 生成**的图片，
   说她躲在隧道里"。→ 两层都塌，但塌的理由不同：一层是事没发生，
   另一层是**画面是造的**。只写"假"，读者学不到任何东西。

2. **事件真 + 表述假**（`factcheck__snopes_005`，美国能源部取消无障碍要求）
   Snopes 评级 `Mixture`。`What's True`：2025 年 DOE 确实改了规则，
   不再要求新建/翻新项目达到 UFAS 无障碍标准。
   `What's False`：最终规则**尚未生效**，2026-07-01 DOE 又把生效日期推后了。
   → 事件成立、表述错。若压成"半真半假"，这层信息就没了。

3. **素材错配（事件可能真）**（`factcheck__snopes_007`，选美选手视频）
   Snopes 评级 `Miscaptioned`：视频本身真，**配的说明错**。
   → 事件层证据不足（视频拍的是别的事），表述层判不实。
   这正是三层存在的理由：只有一层的话，这张卡无论填"真"还是"假"都是错的。

## 2. 每层要什么证据

| 层 | 可采信的证据 | 不足以判的证据 |
|---|---|---|
| 事件层 | 对方阵营/第三方核查/官方通报；通讯社报道 | 同一阵营多账号转述、只看热度 |
| 素材层 | 原始视频源、反向图搜命中、核查站对画面的点名 | "看起来像 AI"的观感 |
| 表述层 | 原文对比（引述 vs 原话）、核查站的 What's False 段 | 语气判断、"太夸张了" |

铁律：**每层都要能指向一句原文**。指不到就写"证据不足"，不许用"综合判断"糊过去。

## 3. 判定词表（本项目统一口径）

脚本产出的是**来源归属判定**，不是脚本自己的结论：

| verdict | 含义 | 卡片显示 |
|---|---|---|
| `source_says_true` | 核查源原文支持该层 | 来源称：成立 |
| `source_says_false` | 核查源原文否认该层 | 来源称：不实 |
| `source_says_media_mismatch` | 核查源点名画面/素材问题 | 来源称：画面不符 |
| `source_mentions` | 原文提及但没给结构化评级 | 来源提及（无评级） |
| `insufficient` | 抽不到可引用原文 | 证据不足（**≠ 主张为真**） |

L1/L2 也是"来源建议"，可被人工覆盖：
`is_fake_source_suggested`（1 假 / 0 真 / -1 未定）由核查站评级映射；
`labels_suggested` 由素材层措辞映射到 `labeling_rules.md` v0.2 的 L2 标签
（`ai_or_synthetic → cgi`、`old_material/mismatch → contradictory_content`、强断言词 → `unsupported_content`）。

## 4. 实现（`prototype/evidence_rules.py`）

```
parse_snopes(body)      抽 Claim / Rating / What's True / What's False / What's Undetermined
split_sentences(text)   中英混排分句（三层引文都以"句"为单位）
media_markers(text)     素材层措辞 → {kind: ai_or_synthetic|old_material|mismatch, quote}
strong_claims(title)    表述层强断言词（只提示，不定性）
piyao_signals(body)     中文辟谣站信号句（先排除"专项行动/倡议书/沙龙"等版式句）
judge_layers(members)   汇总三层：核查源优先，抽不到即 insufficient
```

设计取舍（都踩过坑）：

- **Snopes 结构直接映射三层**：`What's True → 事件层`、`What's False → 表述层`、
  画面类措辞 → 素材层；`Miscaptioned → 表述层（素材错配）`，事件层留空。
- **piyao 不做结构性判定**：它的语料里混着大量专项行动通报和倡议书，
  出现"辟谣"往往只是站名/口号（"e起辟谣 清朗有我"）。所以加了
  `PIYAO_NOISE` 版式句过滤 + `PIYAO_CLAIMISH`（同句须有"称/网传/消息"等主张词），
  宁可漏，不可假阳。
- **`insufficient` 是正常结果**，不是失败：它精确标出"这里需要人去查"。

## 5. 覆盖率的真实数字（2026-11-03，96 个事件簇）

| 层 | 拿到来源证据 | 其中 |
|---|---|---|
| 事件层 | 22 / 96 | 成立 9 · 不实 5 · 来源提及 8 |
| 素材层 | 3 / 96 | 画面不符 3（AI 生成 / 旧素材 / 错配） |
| 表述层 | 8 / 96 | 不实 8 |
| **任一有证据** | **23 / 96** | `status=source_grounded` |

为什么只有 23/96：语料里只有 30 条核查源案例（Snopes 15 + 辟谣站 15），
其余 68 条是 YouTube/X 的主张本身，**没有核查结论可抽**。
这不是脚本的缺陷，而是语料的结构性欠账——也正是 roadmap 里
"按核查源主张反向采集"要解决的事。

## 6. 人怎么用这套东西

1. 打开 `reports/card_<事件>.md`；
2. 先看第 1 节成员表：每条都能点回原帖；
3. 看第 2 节三层表：有「来源称」的层直接用（引文就在下方，
   可点开原始核查页复核）；写「证据不足」的层，按第 4 节的检索式自己查；
4. 查完把结论回填到 `metadata/verify_packets.json` 对应事件，
   并把 `status` 从 `initial` 改成 `verified`；
5. L1/L2 若要进数据集标注，按 `labeling_rules.md` 双人独立标、算 kappa。

## 7. 扩展方式

- **新增核查站**：写一个 `parse_<site>(body)`，把结论段与评级规范化后塞进
  `members[].parsed`，再在 `judge_layers` 里加一个分支；
- **补词表**：`MEDIA_MARKERS`（新平台惯用措辞）、`STRONG_CLAIM_TERMS`（新强断言词）；
- **换语言**：`split_sentences` 已按中英句末标点切分，日语等需补标点；
- **不要做的事**：不要为了让覆盖率好看去放宽 `PIYAO_NOISE`——
  假阳比漏判更伤可信度，一张错的卡会毁掉整批卡的信誉。
